# v0.1.0-alpha.127

A security release: the assistant's limits now hold where its tools run,
standing permissions are confirmed outside the app's window, and the
configuration nenva downloads must be signed by us.

## Changed

- **"Always allow" asks once more.** When you choose Always for something
  the assistant does (sending email, running a command, reading a site), or
  loosen a limit you set on a standing permission, a small Mac window asks
  you to confirm. Nothing inside the app can grant a standing permission on
  its own any more.
- **Groundwork for the iPhone app.** Thread drawers, answer charts and
  commitments now run on the code the iPhone app shares with the Mac, so the
  phone can draw the same things from the same records. Nothing about how
  they look on the Mac changes.

## Fixed

- **The assistant cannot use a tool it was not given.** A tool held back
  from a conversation (in a private chat, while reading an email or a web
  page, or in a routine that may only read) is now refused when called, not
  only hidden, and is refused before any approval is asked.
- **Downloaded settings are verified.** The model catalog, engine downloads
  and feature switches nenva fetches are signed, and a copy that does not
  match the signature is ignored.
- **Links never open an app window.** A link that asks for a new window opens
  in your browser; anything that is not a web address is ignored.
- **Facts the assistant saves name the right chat.** When a routine and a
  chat ran at once, a fact could be filed under whichever chat was on screen.
