# v0.1.0-alpha.39

Your Mac's Apple apps join in: import Reminders into Tasks, Notes into
Notes, and see this Mac's Apple Calendar events in the Calendar — all
read locally from the Mac itself, no Apple ID or password involved.
Tasks also gain a tag system, born from Reminders lists.

## Added

- **Apple Reminders → Tasks.** Settings › Accounts › Apple apps imports
  this Mac's open reminders as tasks — due dates, times, and repeats
  (daily, weekly, monthly, yearly) included. A list picker chooses which
  Reminders lists come along, each task is tagged with its list name,
  and completing a reminder in Apple's app marks the task done here on
  the next import. Read-only: nothing is ever written back.
- **Apple Notes → Notes.** Notes import with their text, tagged
  `apple-notes`; locked notes are skipped. Meant for one Mac — imported
  notes reach your other Macs through Anjadhe's own sync.
- **Apple Calendar in the Calendar.** Events from this Mac's iCloud and
  local calendars appear as a read-only mirror with their own
  "Apple Calendar · this Mac" row in the accounts rail, scoping like
  any account. Google-account calendars on the Mac are deliberately
  excluded — Anjadhe syncs Google Calendar itself.
- **Task tags.** Tasks carry tags now: a Tags row in the task editor
  (search existing tags or create one in place, the notes editor's
  picker), quiet tag chips on task rows, and a Tags section in the
  Actions nav — "All tags" plus a row per tag — for finding tasks by
  tag.

## Changed

- **Turning an Apple import off removes what it brought in.** The data
  still lives in the Apple app, and switching back on re-imports it —
  the same model as Gmail, where the source owns the mail.

## Fixed

- **Notes: a tag view with the sidebar hidden had no way back.** The
  list now shows a "← All notes" chip whenever a filter is active and
  the filters sidebar isn't visible — including the empty-tag case,
  which was a dead end.
- **Memory: the assistant's background note-filing no longer stalls on
  a big backlog.** The compaction pass sized its reply for a small
  batch, so a backlog truncated the output and nothing was ever
  absorbed; the reply cap now scales with the batch and partial
  results are kept instead of discarded.
